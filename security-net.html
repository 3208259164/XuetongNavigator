Jellyfin

官网 ↗原文

Jellyfin 是尊重隐私的替代 Plex 里最干净的那个：不要厂商账号、不依赖云、什么都不回连。取舍是配置功夫：服务器你自己跑，媒体库自己管，转码出问题自己排查，这些 Plex 过去替你抹平了。实时转码的硬件要求视你的库而定，也可能不低。愿意在初次设置上投几个小时，Jellyfin 把媒体服务器完全交给你，对第三方没有持续义务。

OpenWrt

官网 ↗原文

用 OpenWrt 换掉路由器的原厂固件，你能拿回多数消费级路由器刻意扣下的控制权：真正的可配置性、厂商放弃硬件很久之后仍有安全更新、没有厂商回连。短板明摆着：刷错镜像或配置搞砸会把设备变砖，学习曲线也陡。想拥有自己的网络、路由器又在支持列表上，选它。想到要救变砖的路由器就发怵，这就不是随手能升级的东西。

Navidrome

官网 ↗原文

Navidrome 只擅长一件事：把你自己的音乐文件提供给任何兼容 Subsonic 的客户端，任何设备上都行，不要订阅、不依赖云。窄的定位既是长处也是局限：只处理音频，不支持视频和播客，手机原生应用依赖 Subsonic 生态而不是自己出。已经有本地音乐库、想要 Spotify 式访问又不想交月费、不想被采集的自建者，它是当下最实际的选项。

Ghost

官网 ↗原文

现代、快，围绕它擅长的事而建：独立发布，原生支持邮件通讯和付费会员，所以想把读者攥在自己手里的创作者会被它吸引。短板是自建 Ghost 比纯文件博客麻烦，很多人最后用了付费托管服务。目标是通讯加订阅的生意，它是为此专门做的。只想搭个小静态个人博客，它就是多余的机器。

Kavita

官网 ↗原文

Kavita 填的是 Jellyfin 这类通用媒体服务器不做的空缺：给数字漫画和日漫收藏提供一流的阅读体验，章节追踪得当，阅读器是专门做的。网页阅读器扎实，但想要原生手机阅读应用的高阶用户会发现选择比音乐那边的 Subsonic 生态少。Kavita+ 是可选的付费订阅，提供高级元数据，核心服务器完全免费且自足。有大量 CBZ 或 EPUB 收藏、想在任何设备上读又不用第三方服务，它值得。

OPNsense

官网 ↗原文

OPNsense 从 pfSense 分叉后走了干净重来的路线：每周的安全更新而不是打包更新、正规的 MVC 架构、全栈的 REST API，让它在今天对多数用户是维护更积极的选项。功能覆盖从家用边缘路由到多 WAN 企业级带硬件故障切换的部署。诚实的短板是硬件要求：OPNsense 跑在专用 x86 硬件或虚拟机上，不是消费级路由器，所以入门成本比刷固件高。愿意专门拿一台机器给它，OPNsense 是免费能拿到的最能打的网络安全平台之一。

官网 ↗原文

Codeberg

官网 ↗原文

Codeberg 是离开 GitHub 又不必自己当系统管理员最省事的方式，因为它把一整套 Forgejo 平台作为托管服务交给你，不用你操心维护。没有广告也没有追踪，这直接来自它的非营利结构：由使用者资助，所以没有理由开采你的代码。诚实的短板是范围。Codeberg 明确面向开源和公开项目，不是大型专有或商业部署的家，你依靠的是共享的社区资源而不是付费的服务保证。你发布开源作品、想要一个有原则又尊重它的托管方，选 Codeberg；代码闭源或需求重，就自己跑一套 Forgejo。

Forgejo

官网 ↗原文

想彻底拥有自己的代码，就用 Forgejo，因为它轻到能在不大的服务器上跑，又完整到能替掉 GitHub 干真活。copyleft 的 GPLv3+ 许可是低调的英雄：它让当年把人们逼离 Gitea 的那种营利性收编在结构上变得困难，项目因此始终对贡献者负责。诚实的短板是你现在成了运营者，现成的 CI 动作生态比微软围绕 GitHub 建的市场小。想要完全掌控基础设施、也要一个社区治理的平台，选 Forgejo；不想把时间花在跑服务器上，就走托管。同一套软件不想维护，Codeberg 替你托管 Forgejo。

Bruno

官网 ↗原文

不想把请求和环境密钥存放在别人服务器上才能用这个工具，就选 Bruno。离线优先、不要账号，集合就是能读也能比对的文本文件，核心以 MIT 许可开源。诚实的短板是成熟度：比 Postman 年轻，插件生态更小，部分团队协作功能在付费档后面。这些都不影响本地客户端，它始终免费。把 API 工作放进 Git 版本管理、想让密钥留在自己磁盘上，就用 Bruno；高度依赖庞大的集成市场，就要权衡这个差距。

giscus

对静态站或开发者博客来说，giscus 各种意义上都近乎免费：没有服务器要维护、没有账单，讨论串活在你已经掌控的仓库里。它不加载广告追踪，也不种画像 cookie，读者不会被卖给谁。诚实的短板在登录：每位评论者都要 GitHub 账号，那归微软，所以身份和存储的评论都经过同一家大公司，普通受众会被登录墙挡走。读者本来就是已登录 GitHub 的开发者，选 giscus。需要更广的读者群不带账号也能回复，Remark42 或 Isso 这类自建引擎更合适。

PrivateBin

官网 ↗原文

零知识设计是真的：解密密钥放在网址的片段里，浏览器从不把它发给服务器，所以即使服务器运营者完全配合，也读不到你的粘贴内容。支持阅后即焚、过期计时，还能加口令做第二层。自建的 PHP 后端部署简单直接。值得注意：服务器仍会记录任何网址的访问时间和 IP，只是不含内容。不信任第三方服务又要分享敏感文本，PrivateBin 是基准。

Remark42

官网 ↗原文

想要真正的评论区又不把读者变成商品，站长就该选它。Remark42 把数据留在你的服务器上，跑的资源几乎可以忽略，不带任何形式的追踪，所以留言的人不会像托管小部件那样在网上被悄悄画像。诚实的短板是没有托管云：容器你自己跑，存储自己指，更新和备份自己管。这让它排除掉只想贴一段就走的人。已经跑着服务器、也在意读者能私下回复，Remark42 是这一页里最强的选项。完全不想自建，才考虑 Cusdis 这类托管方案。

paaster

官网 ↗原文

paaster 走与 PrivateBin 相同的零知识路线，但建立在更新的原语上：libsodium 的 XChaCha20-Poly1305 secretstream 加 Argon2id 密钥派生，与 VERNAM 同一套栈。加密不是一个可以开启的模式，而是唯一的模式。粘贴历史、阅后删除、二维码分享都内置，项目还刻意避免动态加载第三方脚本。它比 PrivateBin 更小更年轻，公共实例也少，自建是最可靠的路径。想要粘贴内容用上当下最强的浏览器端加密，它是个扎实选择。

Formgrid

官网 ↗原文

静态站只需要一个能用的联系表单、又不愿把回复交给托管服务，Formgrid 是轻量答案。你保留自己的 HTML，把表单指向自己的实例，提交落进你自己跑的数据库，进来时还会过一遍垃圾筛选。MIT 许可是最宽松的那档，所以你能随意部署和修改。诚实的短板是年轻：由一位开发者带领，还在成熟中，后端要你自己跑、自己打补丁。能自建、想要一个完全属于自己的表单端点，选它。不想跑服务器，托管的搭建器是更容易的路。

Bunny Fonts

官网 ↗原文

今天就想离开 Google 字体又不动设计，Bunny Fonts 是阻力最小的路。样式表里换一个主机，字体渲染完全一样。因为服务不记录任何东西，那个让站长吃官司的访客 IP 传输就自然不再发生。诚实的短板是你仍在发第三方请求，只是发给一个尊重访客的主机。必须零外部请求的站点，自建网页字体更干净。想当天改完、不动构建，就用 Bunny Fonts，这是多数站长最容易拿到的隐私收益。

gitGost

官网 ↗原文

匿名向 GitHub 推送：把 gitGost 加为 git 远程，它会以剥掉姓名、邮箱和提交元数据的方式提交一个拉取请求，可选走 Tor。匿名并不完美，托管服务也曾因滥用而停摆。

Neovim

官网 ↗原文

Neovim 是给想要完全控制、不让任何东西离开自己机器的开发者，在隐私这一点上它是这里最干净的：没有遥测要关，因为从来没内置过。这份能力有真实代价。学习曲线陡，模态编辑要几周才觉得自然。舒服的配置意味着自己拼装并维护，而不是装一个打磨好的 IDE。它是终端里键盘驱动的工具，不是点选式的。整天待在终端、也愿意花时间调它，就用它。想要一打开就能干活的编辑器，就别。

VSCodium

官网 ↗原文

VSCodium 是保留你已熟悉的编辑器、又切掉向微软上报那部分的最低摩擦方式。设置和快捷键照旧迁移，遥测在构建层面就没有了，而不是藏在一个要你信任的开关后面。诚实的短板是扩展仓库：微软 Marketplace 的条款禁止第三方构建使用，VSCodium 改从 Open VSX 取，覆盖多数流行扩展，但不包括少数专有的。想要没有追踪的 VS Code、关键扩展都在 Open VSX 上，选它。依赖微软独占扩展的，才需要考虑别处。

Zed

官网 ↗原文

追求原始速度就选 Zed，它的 Rust 内核让它在多数开发者正在离开的那款编辑器面前明显更快，多人协作对结对也真的有用。诚实的短板是遥测：默认开着，所以隐私是要你主动选的，而不是起点，得先去设置里关掉。生态也比 VS Code 年轻，插件长尾更薄。看重性能和协作、也愿意第一天就关掉遥测，选 Zed。想要开箱零收集、或依赖成熟扩展目录，就别。
