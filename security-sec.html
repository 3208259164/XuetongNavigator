文件加密17

7-Zip

官网 ↗原文

高压缩率的文件归档工具，内置加密功能。开源，支持 7z、zip 等多种格式。

VeraCrypt

官网 ↗原文

它是 TrueCrypt 的延续，至今仍是全盘加密与加密容器的参照工具，还有隐藏卷这一手，用来应付需要否认得了的场合。麻烦在于它复杂且不留情面：忘了密码，或者系统加密中途出错，可能就永久锁死了。适合那些会认真读文档、要给磁盘和分区加密的人；只想保护几个文件，则属杀鸡用牛刀。

Cryptomator

官网 ↗原文

快速为文件加密，加密后再上传到云盘，云端只看到密文。开源，支持 Windows、macOS、Linux、安卓和 iOS。

OpenKeychain

官网 ↗原文

安卓上的 OpenPGP 实现，管理自己和联系人的密钥，可与 K-9 Mail、FairEmail 配合，在安卓设备上收发端到端加密邮件。

Tomb

官网 ↗原文

开源的 Linux 命令行工具，基于 dm-crypt 与 LUKS 创建和管理加密卷。把内核加密栈封装成简单脚本，可选隐写式密钥隐藏和 FIDO2 支持。

GnuPG

官网 ↗原文

GnuPG（GNU 隐私卫士）是 OpenPGP 标准的自由实现，GPL 授权。命令行工具，支持 Linux、macOS、Windows，可加密与签名文件及邮件，并管理公钥目录。

Kryptor

官网 ↗原文

免费开源的文件加密与签名命令行工具，支持 Windows、Linux、macOS。通过 libsodium 使用 XChaCha20-Poly1305、Argon2id、Ed25519 等现代算法，无配置项，可选加密文件名。

BitLocker

官网 ↗原文

Windows 专业版、企业版和教育版内置的全盘加密功能。使用 AES-XTS 加密系统盘和固定数据盘，可选由 TPM 支持的启动前认证。

Email Encryption

官网 ↗原文

GnuPG 仍是加密与签名文件、邮件的标准，没有别的东西有它的寿命和互操作性。对体验要诚实：密钥管理是真的难，那些著名的易用性问题正是多数人悄悄放弃 PGP 邮件的原因。必须和已经在用它的人交换签名或加密消息，值得去学；私密对话，现代通讯工具好过得多。

FileVault

官网 ↗原文

对 Mac 用户来说 FileVault 是最无缝的加密选项：内置、免费，在苹果自研芯片硬件上，底层加密在存储控制器层面由硬件强制。恢复可以绑在 iCloud 账号或本地恢复密钥上，这个选择很要紧：iCloud 恢复意味着苹果在技术上可以协助执法。和 BitLocker 一样它闭源，实现无法独立验证。对多数 Mac 用户是正确的默认，但威胁模型强的人要仔细权衡 iCloud 恢复的代价，改选本地密钥。

Gpg4win

官网 ↗原文

Gpg4win 通过 Kleopatra 的点选界面把 GnuPG 的能力带到 Windows，也是 GnuPG 项目为这个平台唯一官方认可的分发。Outlook 插件 GpgOL 让企业环境不必另装邮件客户端就能加密邮件。取舍是只做 Windows，而 Kleopatra 虽然打磨过，仍会把密钥管理的复杂度摊给只想加密一个文件的用户。已经在 GnuPG 生态里、或需要 Outlook 集成的 Windows 用户，它是个好选择。

GPG Suite

官网 ↗原文

GPG Suite 是在 Mac 上用 OpenPGP 最顺滑的方式，干净地集成进 Apple Mail 和 macOS 服务菜单，不用离开日常流程就能加密和签名。核心工具免费开源；GPG Mail 在 30 天试用后要继续用需付费支持方案，个人使用要把这笔成本算进去。只需要命令行加密文件就别选；目标是 Apple Mail 集成，就用它。

LUKS

官网 ↗原文

LUKS 是 Linux 上事实上的磁盘加密标准，各大发行版都附带，Tomb 和多数图形安装器这类上层工具都拿它当地基。密钥槽的设计让你能给单个加密卷加最多八个独立口令或密钥文件，对备份密钥和多用户环境很有用。它是底层积木而不是终端用户应用，所以配置要在命令行或发行版安装器里做。想完全掌控 Linux 分区加密就直接用 LUKS；想要有人引导，就用 Tomb 这类包装或发行版安装器。

age

官网 ↗原文

简单、现代、安全的命令行文件加密工具，同时是 Go 库。特点是显式的小密钥、没有配置项、遵循 Unix 式的可组合。

SeaHorse

官网 ↗原文

管理加密密钥和密码的应用，与 GNOME 钥匙环集成。

PGP Everywhere

官网 ↗原文

iOS 上加密解密文本的应用。有原生键盘集成、钥匙串支持和应用间集成，在任何应用里都能快速用。

FlowCrypt

官网 ↗原文

在 Gmail 里使用 PGP 的浏览器扩展，支持 Chrome 和 Firefox，安卓与 iOS 有手机版。

密码管理器16

KeePassXC

官网 ↗原文

离线、不上云、不要账号、不订阅，密码就放在一个完全由你掌握的数据库文件里。这种所有权是双向的：备份要你自己负责，弄丢了也是你自己的事。它适合本来就有备份习惯的人，会让那些希望换个新手机密码就自动出现的人受不了。安卓端是另一个应用 KeePassDX，不是官方顺滑接续。把本地掌控看得比便利更重，选它。

Bitwarden

官网 ↗原文

这是第一选择，理由很简单：开源、经过审计、个人使用免费，各平台都能跑，不必在便利与信任之间二选一。实话实说的前提是，用官方云端意味着你的加密密码库放在别人的服务器上；介意的话可以自建。对大多数想摆脱浏览器自带密码管理的人来说，第一个该装的就是它，不用附加条件。

KeePassDX

轻量的开源安卓密码管理器，兼容 KeePass，凭据存储在本地加密数据库（.kdbx）中，支持生物识别解锁、自动填充、TOTP 和通行密钥。

AliasVault

官网 ↗原文

如果喜欢 Bitwarden 但不想同步或存储密码，LessPass 是另一种思路：按主密码和站点信息现场算出密码，不保存任何数据。支持浏览器、手机和命令行。

KeePassium

面向 iOS 与 macOS 的 KeePass 兼容密码管理器，支持生物识别解锁、密码自动填充、与 iCloud 云盘等自动同步，读写全部 KeePass 数据库格式。

gopass

官网 ↗原文

用 Go 编写的开源命令行密码管理器，兼容 Unix pass 的存储格式。凭据用 GPG 或 age 加密并纳入 git 版本管理，提供 Linux、macOS、Windows 安装包。

1Password

官网 ↗原文

面向个人、家庭和团队的商业密码管理器，支持 Windows、macOS、Linux、安卓、iOS 及主流浏览器。采用双密钥架构，把主密码与本机生成的 Secret Key 结合使用。

NordPass

官网 ↗原文

Nord 家族里打磨过的密码管理器，经 Cure53 审计，覆盖所有主流浏览器和平台，为想省事的人而做。取舍是闭源，审计结论就是你的保证，而不是能自己读的代码。跨设备的顺滑和支持对你最重要，它站得住；坚持开源的，Bitwarden 或 KeePassXC 更合适。

Proton Pass

官网 ↗原文

真正成立的是集成：已经在用 Proton Mail 或 VPN，Pass 就能顺滑嵌进去，内置 SimpleLogin 别名，注册时不必离开应用就能生成一个一次性地址。代码开源且经独立审计，隐私说法不只是营销。短板是最有价值的部分假定你在广泛投入 Proton，免费档在别名和保险库上比付费版紧。想用一家可信公司管邮件、VPN 和密码，它值；不愿意把一切放在一个屋檐下，则不然。

Spectre

官网 ↗原文

和 LessPass 一样，它按你的名字、站点和主密码现场算出密码，所以什么都不存、不同步、也泄不出来。同一模型带来同样的硬取舍：泄漏的密码没法悄悄更换，没有保险库也就没有备注和附件，某些平台上更粗糙。专门想要无状态方案的人，它是个小众工具；对几乎其他所有人，带保险库的存储式管理器是更稳妥的推荐。

Psono

官网 ↗原文

为团队自建密码管理器是小众需求，Psono 填得比多数好：客户端代码开源，服务端也开源，端到端加密意味着服务端运营者从不见明文凭据。诚实的短板是复杂：自己跑 Psono 需要服务器、数据库和持续维护，小团队未必有这个能力。不想背运维又想要功能，它有托管云方案。需要简单的个人保险库就别选；需要完全掌控基础设施的团队机密，认真考虑它。

KeePass

加固、安全、离线的密码管理器，不内置云同步，被视为安全密码管理器的黄金标准。配套客户端有 Strongbox 与 KeePassium（Mac 和 iOS）、KeePassDX（安卓）、KeeWeb（网页版或自建）、KeePassXC（Windows、Mac、Linux）。更多客户端和扩展见 awesome-keepass 清单。

2of3 by Ente

两步验证11

Ente Authenticator

官网 ↗原文

少见的一款开源两步验证应用，做端到端加密的云端备份，并在安卓与 iOS 之间同步，解决了只用离线的应用换手机就头疼的问题。你把加密备份托付给 Ente 的服务器，但加密才是重点，不想这样也可以用离线模式。想让验证码在手机丢失后还在、也能跨平台跟随，它是最省心的推荐。

Aegis Authenticator

官网 ↗原文

如果你在安卓上，想让两步验证码加密存储、备份完全由自己掌握、整个过程不牵扯云端账号，就选 Aegis。只用离线的另一面是换新手机得手动导出再导入，还得记得去做，而且根本没有 iOS 版。想要开源、加密、不要账号的安卓用户，它是突出选择。

Yubico Authenticator

官网 ↗原文

把 TOTP 密钥从设备挪进硬件，比任何基于手机的应用都是实质的安全升级。手机被偷、电脑被攻破，攻击者没有那把实体 YubiKey 仍然生成不了验证码。短板是依赖：你必须有一把兼容的 YubiKey，丢了又没备份，就等于丢掉存于其上的所有账号。这让备份纪律不可妥协。已经随身带 YubiKey 用于通行密钥或 SSH 的人，这是理所当然的配套应用；其他人则要面对硬件成本与备份要求，门槛高于 Aegis 这类应用。

Tofu

官网 ↗原文

Tofu 是刻意做小的、易用的 iOS 专用验证器，给只想要干净应用、不要求别的的人。它的简单既是吸引力也是局限：不支持跨平台，开发也很安静，别指望持续的新功能。看重清爽、不加修饰的 iPhone 用户，它是个好选择；想要加密的跨设备备份，就看 Ente。

2FAS

官网 ↗原文

2FAS 靠浏览器扩展这一手赢得位置：在电脑上点一下，而不用抓手机眯眼看六位数字。它开源、跨平台，不过依赖浏览器扩展和设备同步，比精简的离线应用多了些运转部件。桌面一键的便利真的合你的日常，就选它；宁愿把一切离线留在一台设备上，更简单的应用更适合你。

Raivo OTP

官网 ↗原文

Raivo OTP 暂时别用。它曾是一款受好评的 iOS 验证器，但被卖掉了，新主人没有澄清换手引发的疑虑，而这正是你不希望守着第二因素的那种所有权含糊。在这一点解决之前，换到维护中、归属明确的替代品，比如 Ente 或 Aegis；等情况真正理清再回头看 Raivo。

安卓上免费开源的两步验证应用，支持加密备份、图标、分类，可定制程度高，还有 Wear OS 配套应用。

硬件与安全密钥6

Nitrokey

官网 ↗原文

相对 Yubico，Nitrokey 的关键差别是透明：固件开源可审计，硬件设计公开，公司位于德国，没有美国管辖的顾虑。Nitrokey 3 覆盖与 YubiKey 5 相同的协议广度。实际的短板是生态打磨：配套应用和文档不如 Yubico 精致，一些企业集成默认你用 YubiKey。想核实安全硬件上到底跑什么，注重隐私的用户，它是强选。

Fairphone

官网 ↗原文

Fairphone 是少见的靠伦理和寿命取胜、而不是靠原始加固的隐私手机。它设计成一把螺丝刀就能拆开维修，更新支持的年数远超多数安卓厂商。诚实的短板是安全深度：它没有 Pixel 那种用来维持验证启动的专用安全元件，所以 GrapheneOS 跑不了，/e/OS 依赖 microG 而不是严格沙箱。可维修性和开箱即用的去谷歌化比最硬的威胁模型更重要，就选它。

Google Pixel

官网 ↗原文

Pixel 之所以是 GrapheneOS 和 CalyxOS 推荐的硬件，正因为谷歌内置了其他安卓厂商省掉的东西：可解锁、刷完自定义系统还能重新锁上的引导程序，Titan M 芯片提供的硬件支撑的证明，以及安卓生态里最长的安全更新窗口之一。讽刺的是，这家全球最大广告公司做的手机，在你换掉系统之后成了它自己最好的隐私硬件。短板很明显：用原生安卓加谷歌账号，你就是把详细画像交给谷歌。Pixel 的隐私故事完全取决于你买下它之后做什么。

NitroPhone

官网 ↗原文

自己刷自定义系统听起来吓人，NitroPhone 把这步去掉：它就是多数专家推荐的 Pixel 加 GrapheneOS 组合，替你做好、密封出厂，还有软件设置复现不了的硬件改动可选。短板是简单的算术。相比自己买同一台 Pixel 再刷 GrapheneOS（免费且有充分文档），你要付实打实的溢价。为了便利和密封的供应链买它，或为了高风险用户才在意的拆麦，就买；能自己跑安装程序，就跳过。

Yubico Security Key

官网 ↗原文

只需要给网页账号和密码管理器做抗钓鱼的 FIDO2 登录，Yubico Security Key 就够，价格大约是 5 系的一半。取舍是范围：它完全去掉了 TOTP、PIV 智能卡和 OpenPGP 支持。对只想止住密码和短信账号被接管的人，这没问题；需要一把钥匙同时管 SSH 密钥或加密邮件的，就该上 5 系。

YubiKey 5 Series

官网 ↗原文

YubiKey 5 是硬件安全钥匙的基准。它在一枚耐用的设备里处理所有要紧的协议：抗钓鱼的 FIDO2 登录、TOTP、PIV 智能卡、OpenPGP，跨所有主流系统，还能通过 NFC 用在多数手机上。诚实的短板是价格：5 系定价偏高，固件闭源，所以你是信任 Yubico 的制造而不是自己审计代码。想用真正的硬件保护替掉验证器应用的人，它值得。

加密 DNS10

Unbound

官网 ↗原文

自己跑一个带验证的递归解析器，是停止信任任何别人 DNS 的办法，Unbound 就是为此而生的精简、审计充分的工具，支持 DoT。代价是你成了运营者：安装、缓存行为、上游选择都归你，这超出多数人的意愿。追求真正独立的自建者和小型网络该这么做；一个信誉良好的公共解析器已经让你满意的，没必要。

dnscrypt-proxy

官网 ↗原文

加密 DNS 的爱好者之选，支持 DNSCrypt v2、DoH，以及匿名化 DNSCrypt，能把问谁和问什么分开。这份灵活也是门槛：它是配置文件驱动的工具，普通用户会觉得比在手机上拨个开关麻烦得多。想精确指定 DNS 走向和中继的人用它很好；只想默认开个加密的人，太过头了。

RethinkDNS

官网 ↗原文

一个开源安卓应用里同时有加密 DNS 和真正按应用区分的防火墙，还不需要账号，这确实少见。拦截库的深度和设备端日志，对想核查应用到底在干什么的人很有吸引力。短板是界面要花时间学，而且 DNS 与防火墙都走 VPN 通道，意味着不能同时和真正的 VPN 并用，除非绕道。愿意投入配置时间的隐私意识安卓用户，用它合适。

DNSCloak

官网 ↗原文

对 iPhone 或 iPad 来说，它通过设备端的 VPN 描述文件把 dnscrypt-proxy 的加密 DNS 带到 iOS，填上了一个真实的空缺。直白的问题是年代：几年没有更新，实际上已被放弃，而一个被放弃的网络工具跑在变化很快的平台上就是负担。改用仍在维护的 iOS 选项；这个只留着当历史背景看。

Cloudflare

官网 ↗原文

快，配置也极简单，支持 DoT 与 DoH，可用率长期很好，所以很多设备出厂就指向它。避不开的张力是集中：把全球 DNS 的一大块交给一家美国大公司，无论其政策如何，都是真实的隐私与集中化顾虑。看重速度和省事就用它；在意减少对大基础设施的依赖，就去找更小的解析器或自己搭。

Nebulo

官网 ↗原文

一个小巧、免 root 的安卓 DNS 修改器，能加 DoH 和 DoT 而不要求系统权限，正好是很多手机用户需要的定位。期望别太高：它已经很久没更新，仍活跃维护的替代品是更稳妥的推荐。确实只想要轻量免 root 方案可以知道它，但先查有没有更新的维护版本。

Control D

官网 ↗原文

Control D 的长处是灵活：可以叠加多个拦截列表、按设备设规则，还能选择把流量从出口节点绕出去，这些基础解析器都没有。免费档对广告与恶意软件拦截确实够用，且不记录日志。短板是完整功能要付费，而流量重定向意味着你要信任 Windscribe 的基础设施。已经超出普通解析器需求、又不想要整套 VPN 的人，选它。

Quad9

官网 ↗原文

瑞士的解析器，默认拦截已知恶意域名，支持 DoT、DoH、DNSCrypt，对多数人来说是隐私与安全兼顾的合理组合。任何公共解析器都有的诚实提醒是：你把信任从运营商转移到了它身上，所以效果只等于 Quad9 宣称的不记录政策。家庭用来当没负担的默认很合适；想把一切都看清并调优的高阶用户会宁愿自己跑。

Stubby

官网 ↗原文

本地的 DNS 隐私存根解析器，走 DNS-over-TLS。它把客户端机器发出的 DNS 查询加密后再送到隐私解析器，提升终端用户的隐私。可以和 Unbound 配合：Unbound 管本地缓存，Stubby 管上游的 TLS 连接。

deSEC

官网 ↗原文

免费、以安全为设计前提的 DNS 托管服务，全部跑在开源软件上，由 SSE 资助。

匿名网络9

Tor

官网 ↗原文

它慢是有意设计的，把这当成缺陷，说明你误解了它的用途。真正需要匿名、也能接受网页按自己的节奏加载时用它，而不是当日常浏览器指望视频流畅播放。就它针对的威胁模型而言，也就是向网络观察者隐藏你是谁、在哪里，没有别的东西可比。追求随手就快，它不合适；真正要紧的时候，它是正确工具。

Orbot

官网 ↗原文

手机上的 Tor 接入，Orbot 是实用的标准做法。安卓上按应用分流是最突出的功能：可以把某个敏感应用推进 Tor，而不拖慢其他一切。诚实的取舍是 Tor 本身比直连慢，iOS 上的架构也比安卓更受限。想在手机上访问 .onion 或抵抗流量分析、也愿意接受更慢的速度，选 Orbot。

IPFS

官网 ↗原文

按星数它是这里最热门的工具，但请把分类看仔细：IPFS 是内容寻址的分布式存储，不是匿名网络，它不隐藏谁在请求或提供文件。把它当成隐私工具是实打实的误解。它的长处是弹性、去重、抗审查的数据共享，完整性比匿名更重要时最合适。目标是隐藏身份而不是寻址内容，它就不是答案。

Lokinet

官网 ↗原文

一个跑在 Oxen 服务节点上的洋葱路由网络，也就是 Session 背后的同一套基础设施，这既是它的差异点也是风险：网络比 Tor 小、受的审视更少，中继基数薄得多。这意味着实践中匿名集的保证更弱，无论设计多巧妙。对混合网络替代方案感兴趣，值得关注和试验。凡是安全真正依赖结果的地方，Tor 的成熟度和规模仍然胜出。

Hyphanet

官网 ↗原文

现在叫 Hyphanet，是一个抗审查的分布式数据存储，定位很具体：你把内容发布进网络，它就持续存在，即使受压也仍可达。代价是慢、操作方式不寻常，完全不像正常浏览，学习投入是真实的。在封禁下架构成威胁的场合，它靠韧性发布赢得位置。别指望它是更快、更友好的 Tor。

I2P

官网 ↗原文

它做的活和 Tor 不同：一个封闭的点对点网络，为网络内部的隐藏服务和种子下载优化，而不是匿名访问普通网站。这份专注也是短板：通过它访问普通互联网只是附带能力，学习曲线陡。想搭建或使用 eepsite、也能忍受配置摩擦，选它。只想匿名浏览普通网站的人，用 Tor 更好。

Retroshare

官网 ↗原文

建立在 GPG 之上的友对友模型，关键区别在这里：隐私来自只与你明确信任的人连接，而不是在陌生人之间匿名。这让它在一个已知的圈子里很强，一旦你想延伸到圈外就弱了。适合想要加密聊天和文件共享、又不要中心服务器的封闭群体。需要广泛、匿名的触达，它的形状就不对。

GNUnet

官网 ↗原文

GNU 的雄心之作，去中心化网络框架，带链路加密，可跨多种协议传输，更像研究级工具包，而不是装完就能用的成品应用。这份广度正是短板：复杂、学术化，并不面向普通采用。对保护隐私的网络设计有技术好奇心，值得探索。日常实际的匿名需求，更成熟、更专注的工具会更好地服务你。

Snowflake

官网 ↗原文

Snowflake 解决一个具体而重要的问题：在封锁 Tor 的地方让 Tor 能用。用 WebRTC 伪装比 obfs4 这类旧传输更难被识别和封锁。短板是它不是独立应用而是传输层，所以只有你已经在用 Tor Browser 或 Orbot 时才有帮助。志愿运行代理扩展，是以极低成本支持被封用户的有意义方式。对不受审查地区、只想保护隐私的用户没有关系。
